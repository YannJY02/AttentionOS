# Issue Tracker

AttentionOS uses GitHub Issues for durable implementation work.

## Repository

- Owner/repo: `YannJY02/AttentionOS`
- Remote: `https://github.com/YannJY02/AttentionOS.git`

## Agent Rules

- Use GitHub Issues for confirmed implementation tasks, bugs, and design slices
  that should survive beyond the current chat.
- Use `docs/work/todo.md` only for early intake and untriaged developer notes.
- Promote large confirmed work into `docs/plans/` before splitting it into
  issues.
- Do not create GitHub issues for broad Phase 4 protocol, SDK, MCP, plugin,
  provider, RAG, or offline-sync work until the owner accepts a narrow Phase 4
  contract.
- If GitHub access is unavailable, draft issue content in the chat or in an
  explicitly requested local scratch file rather than silently inventing another
  tracker.
